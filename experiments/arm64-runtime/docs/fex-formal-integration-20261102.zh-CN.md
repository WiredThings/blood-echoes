# FEX 本机预编译的正式接线

状态：已完成隔离接入验证和最终包启动/F3 回归，安装为本机 Blood Echoes 0.2.61（c9f6b81）。未发布 Release。

复用现有补丁后映像导出、bbcpu 独立静态扫描器、FEX 原生生产器、分片/对象断点复用与按需单元加载。扫描器只链接解码器，不构建或加载 bbcpu 引擎；运行时兜底仍是同一 FEX 的 JIT。生产程序包只携带工具，不携带游戏生成物。

## 正式入口

新增 FEX-COMPONENT 声明，绑定已经复制/重定位/签名的真实 CPU、原有嵌套 CPU 别名、单独扫描器及依赖摘要。Python 与原生代码分别接入原正式应用代码准入；开发路径仍沿用旧隔离限制，不能用一个环境开关把私有代码冒充正式包。

准备数据是原启动器数据根下新增的 `fex-preparation`，与游戏/正常存档分离。导出限于有效映像输出、原始 ELF、产品代次和计划的精确角色，不放开任意用户目录。原生生产器/加载器继续验证真实补丁后代码、FEX/桥 ABI、配置与逐单元摘要，只将需要的代码放入原可失效 JIT 缓冲。生产器强制目录代次与真实编译身份相符，防止写入错误代次；运行时读取则由原加载器用完整实际身份验证，不把选择了旧代次直接变成退出错误，仍保留原 FEX JIT 回退。

正常源码构建增加 scanner-only 目标，打包封存工具声明和实际依赖。没有引入第二套前端、F2/F3、自动继续或退出码协议。

## 增量调度

无变化时直接使用登记的有效映像、扫描和索引，不启动 exporter/scanner/compiler。新捕获仅更新有关计划；原生产器复用既有分片。F3 只在原 GPU/supervisor 证明返回同会话命中后，延后新捕获的枚举和消费；不把尚未编译的新记录登记为完成。下一次普通启动正常增量处理。索引损坏、修复请求和真实输入变化不被该捷径跳过。

在线/离线选择及真实网络模块进入导出调度身份，与原生身份一致；在线时缺省 ARM 网络准入按原生策略启用，显式关闭仍保持关闭。不保存凭据。所有源文件用一次登记，避免网络模块登记覆盖共同源文件登记导致重复摘要读取。

GPU 侧的暖启动/F3 调度、b6042c31 临时归档事件过滤、完整产物/键准入保持。

## 已验证和待验证

源码测试 230 项通过（含继承的原正式入口回归，非 230 项新测试）；原生元数据准入 46 项、独立数据路径正反例通过。覆盖正式角色/摘要不符、路径别名/越界、在线切换、缓存切回、损坏索引、修复请求及 F3 延后捕获。定向测试没有执行血源，不能代替实际采用、探索卡顿或内存验收。

## 实际采用、复用和最终包验证

首次空隔离目录已自动完成 GPU/FEX 准备，FEX 阶段约 461 秒，真实运行命中超过 5.8 万次、拒绝为 0，整分片读取为 0。首轮完整场景采样混入第二次加载过渡，原样保留为 incomplete，不当性能验收；之后相同隔离副本的完整场景/暖启动/F3 均通过。

首轮捕获之后，原生产器仅补 208 个分片、复用 46,777 个分片，约 7.68 秒；后续无变化启动 exporter/scanner/compiler 全为 0。F3 使用原同 supervisor 证明，延后新捕获枚举，准备约 8 毫秒，三个子进程均为 0；没有把未消费的新捕获写成编译完成。

最终 c9f6b811 重新登记其真实 CPU/桥兼容身份，首次 FEX 准备 415.36 秒；随后按新捕获增量补准备 9.35 秒。无新增输入时 2.63 秒，无 exporter/scanner/compiler；F3 为 7.77 毫秒，仍无子进程。GPU 的未变化准备与同会话 F3 证明均实际命中，模块/管线整批准备被跳过。

最终程序包三轮分别 sampled / sampled / functional-checked，均完成守护器要求的完整窗口；实际 CPU/GPU 进程替换、离线恢复和自动继续协议均观察到。它是脚本调用原 quicksave/quickload API 的测试，不是物理键盘或联网/手柄重新验收。前端隔离检查确认版本、仅支持的 FEX 后端、原生 Metal、现有优化选项及已校验汉化状态；未用 Cua 启动游戏或参与性能采样。

## 探索短路线交错对照

真实 CPU/GPU/依赖字节相同的两个源码包，仅移除独立代码副本里的自动 FEX 声明作为原 JIT 对照；不删缓存、不调画质。使用相同隔离正常存档、同一预热 GPU 根和原 runtime_pad，独立发现/准备轮后按 A1/B1/B2/A2 回放。保留用户录制的转镜头段及首 8 秒步行，共 41.5 秒，不重复以前不合格的完整路线。

三组相机走廊比较均通过原 1.5 / 0.6 门槛，最大水平差 0.685、垂直差 0.066；这不是完整地图/战斗一致性证明。路线内没有 Metal 源码或 PSO 编译。

## 耗时和限制

预编译目的主要是减少游戏中现场 CPU 编译，不要求平均 FPS 明显上涨。它仍有代价：FEX 的磁盘单元、元数据和重定位需要在进程里加载；这不是再次执行离线编译。最终样本的完整无变化启动 36.90 秒，F3 从 quickload 请求到恢复场景 31.51 秒；前一纯 JIT 控制暖启动 19.49 秒，准备/包切换条件有差别，不能当逐毫秒归因。但已确认预编译运行时载入仍较慢，不能把 8 毫秒的 F3 准备时间说成完整重开时间，也不声称恢复到旧 5 秒。

全新普通启动、真正的补丁后代码/ABI/主机配置变化可能需要本机准备；现有有效产物保留并增量复用，在线/离线真实兼容身份区分，尚未准备过的模式需要补准备。启动前完成准备不等于全部运行时组合都被覆盖；真实缺项继续用同一个 FEX 的 JIT。
