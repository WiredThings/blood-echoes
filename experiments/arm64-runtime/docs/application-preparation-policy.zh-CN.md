# 正式启动与 QA 内存保护分离（2026-10-28）

正式日志的退出发生在启动准备阶段：fixed helper protection stop: unexpected >2GiB swap growth，随后返回 74，游戏尚未启动。根因是复用隔离测试的准备控制器时，QA MemoryPolicy 及若干边界硬编码检查进入了正式启动路径。此前打包/回归未覆盖“正式准备期间系统 swap 累计增长超过 2 GiB”的情况，属于集成遗漏。

正式路径依据已准入 RuntimeProfile 选择 application preparation；普通启动、F3/暖复用边界、本机库 builder、fixed helpers、PSO controller 和实际 PSO worker 均不安装 QA 停止策略。不会因为 2 GiB 累计增长、1 GiB/5秒增长、锁屏或系统压力等级触发测试退出。选择不依赖可伪造的环境开关。独立开发 CLI 无正式 profile 时仍采用原 QA 策略；外部 QA harness 测试同一正式包时，仍由外层保护负责停止自己拥有的测试进程。

这项分离不改变编译算法、完整键、实际路径/库/收据/权限/变化历史准入、单进程互斥、分批与并发、输入/日志/输出/磁盘窗口上限、编译器与工作阶段超时、取消信号及原退出码。正式版没有新增后台游玩监控，也没有把错误视为成功。真实校验失败仍明确拒绝。

新增定向反例使用合成观察，不实际分配额外内存：正式主准备边界在 swap 增长 16 GiB、锁屏、严重压力样本下不因 QA 判据退出；私有同样样本仍触发原停止策略。实际准入的形式 app scope 用于固定助手和 PSO worker 的打包/子进程合同，禁止它们调用 QA 健康观察；准备超时、并发排斥、原生成功/失败与输入拒绝仍验证。

219 项相关定向回归通过（原有 QA/队列/输入准入/F3/暖复用等测试与新超限反例）。没有实际制造 16 GiB 内存或 swap 占用，超限情况由合成观察验证。

实际候选包的已准入 RuntimeProfile 在全新私有 GPU 目录完成 22 份 Metal 库及 8 类助手准备（2 次实际 native 调用），助手 QA 健康观察调用 0。外层独立测试仍使用未修改的 QA MemoryPolicy，17.78 秒完成，压力前后 1，swap 无增长，没有启动游戏。早期测试夹具遗漏原 Local AOT 记录环境，被原 native 准入以 verified helper cohort 拒绝；补齐原环境后通过，未放宽校验，也未把该轮算成功。
