# 模块地址查询和析构地址匹配接入（2026-10-25）

本轮在隔离 ARM64 执行组件中成对实现 `sceKernelGetModuleInfoFromAddr`、`__elf_phdr_match_addr`。连同上一轮 `__progname`，原九项遗留接口已实现三项，另六项仍未完成。没有发布正式版；白模、长编译和实际场景性能改善仍未证明。

## 复用原加载器，保留原前端流程

原16个启动准备源码逐文件 SHA 核对不变。`prepare.py` 和其依赖 `game_check.py` 字节不变地复制到组件的 vendor/blood_echoes/loader，来源摘要记入 SOURCE.json；不是第二套前端策略。ARM 组件在原脚本生成 BBPROBE5 后、FEX/GPU 初始化前，调用这份原 SELF/ELF 解码器读取本机固定 1.09 的 eboot、libc、Fios2。只需要程序头和动态初始化字段，不再建立无用的符号/重定位大表。

生成器仅写本次私有 state 下的 `.arm-module-info.bin`，原子替换单个文件，不产生历史副本。包含原 boot SHA256、image 大小及3个 ModuleInfoEx 描述；没有游戏代码、纹理、着色器或存档。父进程在助手退出后验证 boot 摘要、描述数量、原加载段/权限、初始化入口、TLS index/范围/对齐、静态/动态 offset、异常展开范围以及已加载 EH header 的实际字节，再对地址统一加 image base。格式错误会在进入客体前失败，不使用全零描述假报成功，也不信任文件中可任意指定的宿主指针。

ModuleInfoEx 为显式客体布局424字节，ARM64/x86_64编译静态断言一致。查询可返回代码和数据加载段的完整描述；合法输出无需预置 st_size，符合已看到的 libc 调用。查询拒绝非法输出、未知地址和非法 flags。地址匹配只检查完整且有效的可执行段范围，使用首地址包含/尾地址排除；不解引用结构体所描述的地址。非法输入指针保留既有74错误退出，不产生宿主崩溃。它处理的是前一轮实际客体调用点传入的 ModuleInfoEx，不是 FreeBSD dl_phdr_info。

字段以本运行时的真实布局为准：主程序静态 TLS 为现有 variant-II offset，模块动态 TLS offset=0；只报告本运行时实际映射的加载段，不伪造不存在的 PT_DYNAMIC 映射。固定加载的3模块构建后不变，查询无新锁或运行时分配；动态加载/卸载支持不是本轮宣称范围。

## 内存与性能边界

原修改后的正常手动QA zip仍未更新，仍冻结CPU09af59d2；本轮是Shared开发执行组件，不能把旧包说成含新修复。正式应用及Release不变；正式11671既有保护文件的逐字节核对见 `module-info-final-20261025.json`，不把它们全称为存档。
