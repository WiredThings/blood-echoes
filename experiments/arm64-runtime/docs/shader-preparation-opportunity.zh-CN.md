# 绘制准备发现提前量与静态游戏目录下一步

本轮未引入异步编译，不修改画质、绘制、现有缓存容量或正式数据。probe 仅由 BB_SHADER_PHASE_AUDIT 显式启用，与现有 gate 一起生效；每个调用线程最多记录 128 个唯一的 hash/阶段/缺失原因，无资源载荷、无动态增长的任务或shader缓存。记录仍使用已有固定1 MiB环。

## 验证

- prep-opportunity-controls-1792896178432600000：七项真实 ARM64 原生门控、去重、不同阶段/原因、预算溢出和关闭控制通过。
- test_prep_opportunity_analysis.py：十二项分析控制通过，覆盖同线程不算提前、发现晚于编译、不同hash/阶段、发布缺口、孤立/重复事件及同一微秒多组有效发布。
- shader-phase-audit-controls-1792895764465351000：七项既有原生分项计时控制仍通过。
- actual-shader-phase-controls-1792895873320648000：自造GCN经真实PipelineCacheCore准备缺失分支，只返回未就绪而未创建模块；随后真实IR/SPIR-V/Metal模块构建成功，诊断开/关SPIR-V字节一致，缺失元数据仅在开启时出现。

最初真实数据中按时间戳分组会把同微秒内两次调用误判为歧义，分析保守拒绝45组，未用其作关联结论。现已改按同线程发布顺序配对并要求完整发布区间、匹配时间和合法身份，补同微秒多组负/正例后离线重算。没有改写原始trace或重跑游戏凑结果。

## 一轮真实隔离探索

observed-combat-driver-1792895899977895000 / launcher-engine-abba-1792895900403107000：使用原入口、隔离QA存档和新建独立私有应用缓存，原正式及既存测试缓存不清理。静音、无Cua/桌面录屏、原内存/swap/锁屏保护。正常主动finish，监督器0退出；QA源存档摘要不变。路线上两次原生present读回都在门控外，故本轮是正确性和归因诊断，不是FPS对照。

GPU6859条完整、无丢失/覆盖；CPU25371条有8987条早期覆盖，不能宣称整个启动CPU覆盖。269个模块的分项均完整。五个准备线程记录371个唯一缺失项（317个程序缺失、54个特化缺失），没有预算溢出或无效配对；195项模块存在同hash/阶段的较早发现。这里没有完整特化快照或等价证明，不能把它们直接当可复用预编译键。

部分启动期片元有40–440ms提前量，而模块本身约17–24ms，说明并非一概“来不及”。但多数发现属于启动。进入场景一秒之后仅13次新模块，只有5个不同模块观察到较早发现；其中新的片元 bd1d09f0（19.668ms）和71874d2c（21.377ms）没有提前记录。全轮最慢模块是启动期compute 42f2a521（478.046ms，后端447.798ms），原绘制准备只覆盖graphics，不能据此声称能消除此compute停顿。不能拿冷应用缓存的一轮启动长帧当正常暖场景性能，也不能将不同特化按hash强行配对。

最终原生图片可见角色衣物/武器材质，未见整身白模；未独立确认本轮敌人接触，不能称实战白模已复现或解决。

## 后续方向

用户明确要求固定游戏目录。已只读找到本地1.09的八个shader/*.shaderbnd*.dcx（含一个debug包）及mtd/allmaterialbnd.mtdbnd.dcx；尚未解包、去重或枚举内部程序，不能称全部shader已统计。应先按固定游戏版本枚举基础程序，再关联材质/效果和已观察的完整特化、管线键，区分可知与未覆盖项；仅对完整输入和生命周期安全的条目评估有界提前准备，不穷举理论组合、不新增常驻全量缓存。
