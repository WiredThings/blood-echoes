# bbcpu 已登记代码与 HLE 快路：隔离集成

## 范围与实现

针对 [CPU 归因记录](bbcpu-cpu-hotspots-20261031.zh-CN.md) 的前两项接入开销。FEX 与 bbcpu 仍是独立进程内执行后端；继续复用原前端、Metal、汉化、联网、输入和 F2/F3 协议。正式应用和正式数据不参与本轮，不发布 Release。

`game_runtime` 在启动安装器与权限设置完成后，把已有 `State.ranges` 和 veneer 所有者的范围登记交给 bbcpu。只读、可执行且不会在进程内释放的区间进入已有 `StaticRangeIndex`；可写重叠排除，两索引分别最多 256 项，超额保持原动态查询。临时栈和可释放 VMA 不进入该代码索引。它只证明代码范围，不授予 HLE 入口身份；另一个索引独立保存 owned HLE 范围。后续新增页和所有未知范围仍调用原所有者。没有成功地址的无限缓存，也不改变页权限或生命周期门控。

复用上游 `RcApi.call/tail → call_import`。候选只有完整 owned 16 字节的 `mov r10,rcx; mov rax,operation; syscall; ret`，或读取经过范围校验的 `ff25` 导入槽后到达该序列。逐次读取槽和入口字节，不缓存可变目标；完整代码跨度、HLE 所有权、立即数、返回槽和原服务参数校验保留。实际派发共用原 syscall handler 和 `HleCallService::Invoke`，保留 GPR/SIMD、嵌套回调、停止请求与原错误码 74。原生裸宿主地址继续 deny-all，未知序列走原 bbcpu 自身路径；不接 FEX 桥，也不绕过资源分配/释放观察及 GPU 同步。

新 embedding 接口放在 `src/bbcpu_import_fast.h`，未改生成静态代码的 CPU 结构、RcApi、ABI 或有序访存 helper。ABI5 合同仍为 `2221241b1aa33aa2426b55096d0683f0fb142ac1a4e2095c8ec23f37d3c9ab0f`。隔离封装保留原扫描器、生成器及其真实摘要，只有 CPU/导出准备角色更新。原游戏库 `c741d0a0d088d55de7c7b2ac288d1cde758c19efdde4d6bea6a039bcbf1d6dbd` 保持；241046/241046 函数匹配、0 changed。更新后重导出用约35.19秒，384对象全部复用、实际编译0；不能把 compile-progress 的 done 数当 Clang 编译次数。

共享 `BB_ARM_RANGE_FAST=0` 会同时关闭代码范围复用。另有仅开发用的 `BB_BBCPU_RANGE_REUSE=0` 和 `BB_BBCPU_HLE_DIRECT=0`，不新增正式用户流程。本轮性能测试采用默认新路径，目标细分计数和 CPU 栈分析均关闭；保留原有每10秒的低开销分批汇总，并新增 owned HLE 列，不开启逐次调用日志。

## 定向验证

11 组 CTest 通过。作者输入的真实静态库使用固定 x86 字节及对应 FNV64，由正常逐函数加载器核验，再实际执行 `RcApi.call/tail`，覆盖七参数、结构体双寄存器返回、SIMD、flags/保留寄存器、嵌套 guest 回调、两个工作线程各64次调用、停止后的 RAII 析构、跨界/溢出/可写重叠、256项预算和后注册页的持续动态校验。关闭快路的原路径也通过同一正例。原生目标、未登记 syscall、错误操作号、坏参数、坏导入槽和 live invalidation 均按原74拒绝；不冒充菜单重启75/76。

原启动选择14项、benchmark相关43项、帧时钟准入14项通过。benchmark夹具补齐旧测试缺少的真实 `FrameProgress` 格式，保留全区间、陈旧/截断/非场景证据的拒绝规则；未修改或放宽实际采样器。测试夹具不包含游戏内容，不能当游戏、联网、死亡或画面验收。

隔离 refresh11 核对：CPU `b1ec518a5c99953005ee8f04ce48ed57e5e4edcc5cb66e1cfe44f1ee8b2c2f92`，导出准备器 `789874e0f95e8882d72169162ce111b884e7db8a3afa66cf797460589799e13a`，FEX、Metal 和联网依赖逐字节保持。实际启动代码索引216字节、HLE索引24字节，均有固定预算，没有新运行期大型缓存。
