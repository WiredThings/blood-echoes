# ARM64 AvPlayer 桥接与线程生命周期检查点

本轮只改隔离原型；正式应用、存档、设置、缓存和 Release 不变。开发分支为 dev/arm64-runtime-audit。

## 实现

复用原生宿主已实现的 16 个 AvPlayer 接口；新增的薄桥负责 guest 函数回调、完整参数跨度、句柄代际和回调数据暂存，不另写播放器或解码器。客体文件读取通过最多 64 KiB 的有界临时块桥接，不扩充持久缓存；原生输出按现有 CPU 写入通知处理。关闭等待在途 API，回调内关闭同一播放器被拒绝，避免线程自我等待。

原始线程包装器只附加 host TCB/TLS。现在复用 runtime_thread_detach_host，通过可选线程完成钩子在工作线程结束时回收；没有钩子的原宿主仍保留原行为。桥接宿主 revision 必须匹配：新版桥与旧宿主的真实链接负例失败，避免静默使用未清理的实现。错误仍为 74，不占用监督器的 75/76 重启语义。

实际游戏导入清单中 16 个 AV 接口均走 native-avplayer，未接导入由 25 降为 9。其余为 sceKernelMlock、sceKernelGetModuleInfoFromAddr、__elf_phdr_match_addr、__pthread_cxa_finalize、msync、_is_signal_return、sigreturn、__Ux86_64_setcontext、__progname；尚需逐项分类及验证，不能称为兼容审计全部完成。

## 正确性证据

- avplayer-bridge-native-1792892864394987000：原实现真实解码自造 16×16 无声视频，线程附加/清理 5/0。
- avplayer-bridge-native-1792895241429154000：新实现同一类控制通过，附加/清理 5/5；两次缓冲分配均释放，文件打开/关闭配对，同一播放器回调中 Close 被拒绝。此控制的回调由原生测试实现，不冒充 FEX 证明。
- avplayer-bridge-native-1792895239951193000：新版桥链接旧宿主被缺失 revision 符号拒绝；没有执行旧库或覆盖成功结果。
- avplayer-fex-1792895039737803000：真实 x86 客体回调经 FEX 执行，分配/释放、rep-movsb 文件读取、事件和 GS/TLS 均受检查；关闭后 handles=0、contexts=0、host-TCB=1/1。五类坏跨度/回调/超量读取负例均以 74 退出，16 个实际 AV 导入正确接入。另有 ARM64/x86_64 结构布局编译检查，不执行 x86 宿主。
- current-runtime-regression-1792893811329890000：56 目标重建后 121 项基础回归及附加 ABI、跨度、时钟、受保护导入、未对齐和 AV 控制通过。这在最终 revision 准入增加前；最终 CPU 又跑 AV 和 exit-contract-1792894379286928000（17 个 FEX 退出、6 组原监督器控制）通过。

最终 CPU SHA256：602795dfa500dbab74d698a0ee971cd9f5ec6a23d55f8de8a61ebc53d0d06e63。实际 AV 宿主 a5005c5f807c861eddd50a31fcf0e64295a463aeff9d33e5097cddf504ab2783，已验证实际 Mach-O 依赖边及严格签名，不仅核对路径字符串。

## 实际游戏与性能边界

launcher-engine-abba-1792893957384904000 的原启动入口冒烟已到场景，16 个 AV 导入命中。最终 CPU 另在 avplayer-component-abba-1792894565416373000 完成静态、静音、同镜头、同设置的旧/新/新/旧对照，各 90 秒，无 Cua、桌面录屏或抓帧：

| 路径 | 两轮 FPS | 平均 FPS | 两轮聚合 footprint MiB |
| --- | --- | --- | --- |
| 旧冻结包 | 48.795 / 48.190 | 48.492 | 6085 / 5808 |
| 新 AV 桥 | 48.594 / 48.652 | 48.623 | 5815 / 5822 |

差异约 +0.27%，属于持平，不能宣称提帧；旧版内存离散较大，也不能宣称节省内存。本组未见额外压力，不等于所有场景内存等价。未主动播放视频，不能用站桩 FPS 验证播放、战斗白模、首次编译、F3、死亡、在线或菜单。

## 限制与后续

白模仍未明确定位或修复。长编译已捕获真实新顶点着色器的 Metal 库 232 ms + PSO 84 ms，关联 338 ms 帧；当前工作不是其修复。HwStage=1 是顶点，已纠正此前误写“片元”的说明，并补阶段名称测试。

AV 测试只覆盖自造无声媒体，不包含音轨、任意编码或所有游戏过场；现实现的非空事件载荷只对原实现使用的 WarningId 已知结构桥接，其它非空载荷明确失败，不能伪造成功。正式入口的跳动画、菜单等仍沿用原配置，尚未做本轮实机全面验收。

源码检查点依赖准备过的私有对象/库构建阶段，尚非 clean-checkout 独立构建。普通手动 QA 包仍冻结在 CPU 09af59d2，不含本轮 AV 新 CPU；本轮新二进制只在私有组件和自动测试中使用。正式数据 11671 个受保护文件的快照仍与基线相同（多数为缓存，并非 11671 个存档）。

下一步优先处理完整 shader/PSO 特化已知时的安全准备时机，并继续白模绑定/失效现场归因，不靠缩缓存、跳绘、降画质或放松同步换性能。死亡、在线和菜单留待用户统一验收；继续监测限额，低于 15% 停止并交付最新 QA 包。
