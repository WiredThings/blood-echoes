# FEX 分片读取与 Metal 屏障：统一隔离验收

源码及本轮 QA 的构建身份：`a70205a0e43feaec84cf3cfe6c74b239ae0078b1`。0088、0089、0090 和 FEX 装入修正已一起构建，不是仅把补丁文件放进应用。FEX/bbcpu 宿主、GPU 进程、模块及 PSO worker 的实际依赖均核对为同一版 renderer；重定位后的库摘要不同，不能据此误判成不同源码。

## 修正与边界

- 0088 保留同一物理 encoder 中 Replay→ContinueDirect 的屏障覆盖；实际绘制重置覆盖，不跨真实依赖删除屏障。
- 0089 只回收底层来源已不存在或 UID 已被替换的场景副本，沿用原 GPU tick/fence 延迟销毁；保留有效、脏内容以及近期白模/彩噪修复。
- 0090 用保留附件的通道续接和真实 fragment→vertex fence 替换 Apple GPU 不支持的 render memory barrier。保留完整已执行状态、MSAA 中间 resolve、查询累计与原退休时序；不是删除 fragment 阶段或关闭 API validation。它有状态快照、额外物理通道及潜在 MSAA resolve 代价。
- FEX 只装入实际完整编译单元，沿用原重定位、源页核验、JIT buffer、块链接和自身 JIT 兜底。完整分片读取/验证及临时输入析构移出 JIT writer 和代码失效 guard；发布时重新取得原锁并检查实际源页、buffer、容量及已有映射。
- 有界元数据登记使同一文件身份的后续缺失只读取所需单元，保留单元 SHA 与读后文件身份检查。没有常驻整片代码，也没有缩小或清空执行缓存。2 MiB 是元数据账本预算，不是整个加载器的物理内存上界。

独立审阅已检查 0090/0089 的 tick、回放、持有列表及延迟销毁，以及 FEX 的输入所有权、锁序与原 JIT fallback 的报告析构位置。定向测试包含真实 FEX 跨进程重定位/执行、两锁被占用时的锁外 IO、单元范围读取、文件改动、损坏摘要、边界/容量拒绝，以及 API validation 开启的实际 Metal 像素/查询/生命周期正反例。定向通过不等于全部游戏场景通过。

## 场景条件

同一 QA 进度，亚楠中心固定镜头 `(-190.784, -27.226, 71.116)`，1920×1080、MetalFX 关闭、原特效/解锁帧率/社区汉化选择保持一致。每组两轮，每轮完整场景时钟约45秒；性能轮无 Cua、截图、录屏或 CPU profiler，音频关闭。原保护保留，警告压力允许继续；没有用保护中止的轮次冒充采样完成。

旧版对照为此前的 Default Vertex 包；新 JIT 与预编译 FEX 使用本轮同源 CPU/Metal。正常无缓存 FEX 不走新增额外预查找分支。bbcpu 使用同一整合 Metal，并复用旧 QA 对象种子（2233文件、1,118,437,452字节）；不复制 ready 凭据，仍由原生成器核验。因此不能将其准备时间当作全新静态编译，与 FEX 首次全目录编译直接比较。

## 读取放大仍存在

修正版 FEX 两轮累计复制约97.8/98.4 MB，容量回退各2次；此前严重回归轮累计复制约9.3 GB、容量回退651次。后者不是常驻内存或实际GC次数。修正版已不再出现此前 loading 约2 FPS 的退化，但这不等于已证明预编译路线优于 JIT。

每进程仍有约4.13/4.14 GB读取、10.45/10.48 GB摘要工作，load累计14.46/11.51秒；JIT writer累计持有约219/221毫秒。冷分片首次准入或元数据淘汰后重验的成本仍明显，不能声称读取放大已归零。whole_reads/evictions计数不能区分每个分片首次接触与同一分片再次验证；末段周期计数不再增长，也不等于排除了所有阈值以下活动。

现有格式以整分片摘要建立可信边界，不能在没有等价依据时删除首次完整校验。若继续减少首次读取，需由原生产器提供可独立核验、绑定完整兼容身份和实际完整单元/重定位的版本化索引；迁移保留旧格式产物。此处只记录缺口，不以任意放大常驻证明缓存或跳过校验消除统计。

## 未覆盖与交付状态

本轮固定场景没有 scene-proxy（MetalFX关闭），因此0089的真实场景节省量未测到；短探针释放量不能算作本轮物理内存收益。没有单独的场景复制字节/物理通道/屏障计数轮，不能把组合结果归因于单个补丁。没有据此宣称完成长期跑图、死亡重生、联网或全部视觉回归。

进程 footprint 合计仅为同口径观察，包含共享映射，不能作为两个进程的物理 RAM 净和；guest alias容量也不能再次相加。唯一分配分类与退休/释放量另行保留在原日志。

正式应用、正式存档、设置、已有缓存与 Release 均未改动。源码和文档同步开发分支；原目标及其他有效 CPU/启动器工作保留，整体目标不因本轮验收结束而标记完成。
