# Metal 随机挂载路径与编译身份（2026-10-28）

同一个 MetalToolchain-v27.1.266.1 重新挂载后，`metal --version` 的 `InstalledDir` 从 NBhkO4 变成 CLrnEw。旧 BuildId 因完整版本输出而变化，实际 OS、SDK、metal/metallib/xcrun 的二进制摘要、版本及编译选项均未变化。这是编译身份混入位置来源的缺陷，属于启动优化范围。

## 修复

仅识别完整的四行 Apple metal 版本输出及已确认的 cryptex 路径布局，将随机挂载后缀规范化。保留真实 Metal 版本、Target、线程模型、Toolchain 资产版本、三个工具摘要、SDK、OS 和 recipe。未知输出格式不变，不删除未知兼容字段。当前识别时核对 InstalledDir 与实际选中的工具链根，原始输出保存在工具登记 pins 中。

实际路径、inode、权限、只读挂载、SDK 选择和连续变化历史仍用于本次准入；路径移动会重新登记真实环境，但不会仅因随机后缀另建编译产品身份。它不等于允许从任意目录载入工具或库。

旧产物保留式采用：在当前 cohort 的有界历史代目录中，先验证原 build.json 的完整摘要等于原 BuildId，再比较规范化后的全部清单；随后验证当前完整原生请求、源摘要、原库收据与实际库字节。成功后新目录发布独立收据及完整原始清单来源。原目录、库和收据不改，不把迁移证明当成原生 entry 或 PSO 已准入。运行时原有完整键、函数、归档与库检查继续执行。

只在未命中整批复用时发现历史代，最多观察 128 个目录项；不遍历全部 cohort，不缩小缓存，不引入 GPU 常驻资源。超过预算保留原产物并走原增量准备路径。
