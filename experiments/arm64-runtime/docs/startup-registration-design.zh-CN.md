# 启动登记、失效范围与产物复用

2026-10-28；开发源码，集中场景验收尚未完成。本机保持 0.2.57 / 2109ed70。本轮不发 Release，不恢复已关闭的纹理／生成链诊断。

## 可直接复用的路径

前端现有游戏目录、Mod 配置／顺序、启用状态、社区汉化来源通过原 `recipe()` 和原合并算法进入资源登记。游戏本体、独立 Mod 来源及最终只读快照各自保留完整清单和变化历史。未改变时不遍历全游戏；外部改文件仍走变化记录；切换恢复已有源时复用原证明。编译域已经与资源选择来源分开，native 完整特化、PSO 状态和运行时准入不变。

已有 required 模块、PSO 调度证明、本机库审计及同 supervisor F3 快速分支继续使用。本轮不重新实现这些流程。

## 本轮登记与键

| 工作 | 登记证明及变化触发 | 不变时 | 与 GPU 编译身份的关系 |
|---|---|---|---|
| 程序包闭包 | 实际四份清单摘要、全部已验证文件身份／字节摘要、App FSEvents 连续历史、代码角色／权限 | 四份实际清单 + 变化查询，整批代码不重读 | UI／调度更新只更新包登记 |
| 单次 Python 内代码检查 | 256 项有界完整 inode/owner/mode/nlink/size/mtime/ctime + 摘要，不保存内容 | 相同实际文件的 digest 共享，仍检查本次 expected 和 limit | 不参与编译键 |
| Mach-O、架构及签名 | 真实原验证结果、实际 target/library 摘要、固定系统工具和 OS 身份、App 历史 | 不再 otool/lipo/codesign；仍重核当前角色、路径、RPATH 唯一解析 | 只把实际 GPU 库身份交给原编译键 |
| 工具环境 | 原 NativeToolchain 完整探测所得 BuildId、工具与 SDK pins、系统/选择、安装目录历史 | 少量选择／系统／文件信息与历史查询；不重跑 xcrun 完整探测 | 登记规则更新不改变 BuildId；真实兼容身份仍为原字段 |
| 只读工具挂载 | 实时 readonly 标记、fsid、挂载和实际文件身份；可变挂载选择父目录、Developer 安装目录事件 | 无需对不提供历史的只读卷假设 FSEvents 成功 | 不改变真实 compiler/SDK 身份 |
| 映像／链接 | 原 eboot、libc、Fios2、SFO 实际字节 + 原解析／链接四文件代码 + BBPROBE ABI | 不重复 prepare/link；已有 out inode 未变则连 CoW 恢复也跳过 | 输出仍是原算法，补丁／运行参数仍原路径生成 |
| Shader 提取完整性 | 原 game_check、所选 shader 路径与历史，绑定实际映像身份和原 skip 策略 | 不重新解包检查不变的 shader；改变则单独原校验 | shader 变化不无条件重新链接 CPU 映像 |
| 最终 boot/content/patch/settings 摘要 | 四个明确输出的完整实际元数据与原字节摘要 | 仅这四项相关文件核对，避免再顺序读取整个 boot | 编译域仍只采用其真正编译字段；来源完整保留 |

包复用复用现有 `Hashes`／journal 机制，显式 code-roots 策略允许 root/current-user 非可写代码目录；数据目录仍只允许当前用户。代码跨启动丢失连续历史则回原代码读取。FSEvents 丢失、coalesce、root/volume/inode 改变等保守规则不放宽。

程序包登记仍需要完整清单。每一原生角色、工具、原脚本必须匹配清单，缓存记录不能新增权限。缓存记录使用私有 owned regular 文件、校验和、完整绑定；并非版本号／环境 flag／布尔 ready。签名登记还重核实际库的 frozen 摘要以及当前 RPATH 唯一解析，不能用合法库摘要冒充别的 load edge。

真实补编译保留原 before/after `_unchanged_full()`。暖重用不是授权使用不确定的编译环境。Xcode/CLT/SDK/Metal Toolchain 可以独立更新，OS build 相同不构成不变证明。新登记和旧产物并存，不清旧库／归档，不缩小缓存。

映像缓存采用原函数生成，APFS CoW 存储、逐输出证明并封存；坏产物仍保留，另建一代。`analysis.json` 是原映像生成时的分析快照，复用时不冒充重新遍历得到的当前全资源统计。是否复用和当前输入来源在单独的 Image/link 日志中记录。

## 真实检查中发现的差异

本机只读 Metal Toolchain 挂载没有可用 FSEvents volume UUID，初版登记因此始终拒绝复用。已改成只读挂载实时身份固定，并监测可变安装和挂载选择目录；没有把“历史不可用”直接当作“未变”。系统验证工具的合法 root hardlink 仅限四个固定系统路径，不放宽 bundle/dylib/数据文件。

新建并 chmod 的产物目录可能晚到一个历史事件，因此第一次重启可能重新核对产物字节。该轮不是零读取快路径；保守重验并重新登记后，后续稳定复用。保留这一事实，不用忽略新事件来美化命中。

真实无游戏工具检查（不是场景性能结论）：包登记首次 57,076,151 bytes / 79 次摘要读取，清空进程内摘要记忆后 11,628 bytes / 四份清单；签名／架构登记第二次 0 个 otool/lipo/codesign，仍有变化历史查询；工具登记第二次 0 xcrun、原 BuildId 一致。原映像／链接产物约 393,287,892 bytes，稳定复用不再整批读取或生成。
