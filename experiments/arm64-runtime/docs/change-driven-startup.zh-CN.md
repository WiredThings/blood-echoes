# 按变化触发启动准备（开发候选）

2026-10-27：用户要求正常启动直接复用，仅在文件变化或校验异常时复检。本轮先在隔离开发包验证；正式数据及现有缓存保持，Release 不更新。

## 已有证据与候选

- 原版28852文件的快照剖析24.31秒中，13.06秒是MemoryPolicy对五秒全部样本重复求最小值；不是游戏内容读取。改为单调队列，保留全部样本验证、时间边界、锁屏、严重压力和swap阈值，12000密集/稀疏随机观察与原算法判定相同，等值历史可归约为一项。
- FSEvents采用逐卷UUID、根目录身份、历史完成、同步flush和FullHistory重叠事件。只忽略已记录的完全相同历史事件；新事件、根替换、丢失/合并/回绕/挂载变化、不可用或5秒查询超时，均恢复原检查。查询使用限量短命子进程，无常驻监听、无游戏中开销。完成回执在校验开始前锚定游标，不能把未验证的后续变动吞掉。
- 源摘要、只读快照和静态输入接入该记录。无变化时跳过逐文件stat及快照/静态目录的整树扫描；原始Mod合并算法与当前app0映射核对保留，静态元数据实际内容摘要及运行时完整键校验保留。提示缺失或损坏先按原逻辑校验登记，后续启动复用。
- 原231库全命中剖析中476次ps占约8.84秒。库复用证书绑定本次实际工具、SDK、OS和请求/产物目录连续事件；无变化时跳过逐库重复读取及其逐项预检，仍执行当前工具身份与实时保护。初始/固定helper/最终阶段共享已有有界PreparationSession，结束释放临时SQLite和观察器。新实际库副本实测登记8.12秒、两次复用0.58/0.50秒，231库、built=0；此为库阶段测量，不是游戏启动结论。
- 已经由原生完整验证的常规PSO可保留预热调度证书，绑定当前编译器/代码闭包、选项、完整manifest及所有输入和产物目录。无变化时跳过重复的预热worker；游戏运行时仍进行完整管线键、产物和资源检查。不会把该调度命中写成“本轮执行了原生验证”。几何owned协议和未知类型保持原native流程，不猜依赖。

## 验收边界

定向反例覆盖相同大小并恢复mtime的改写、增删、根替换、非法链接、查询失败、库损坏、SDK变化、源变化、PSO代码/选项/manifest/输出变化和采用前变化。首次登记后的历史批次可能仍包含冷构建的写入，必须保守复检，不能为提高命中率放宽事件解释。

上一轮“首次暖启动”包含首次进场后新增输入的本机编译与模块准备；它和稳定暖启动不同。本轮整包对照计划分别测：冷启动、首次补编译的暖启动、稳定暖启动。四分半不能作为所有后续启动的固定成本；分项夹具结果也不能当作整体性能结论。

当前尚未接受整包启动/内存结果，不更新正式应用；代码与测试记录按现有开发分支同步，不发布Release。

## 原生预热失效噪声与字节证明收口

实际相同190条完整输入的两轮 manifest 字节完全相同，事件记录仍含临时发布文件及 `.key` / `.hostpso` / JSON 的扩展属性变动。不能简单忽略这些事件；新候选在**真正完整原生验证前后**分别对相关编译缓存做有界流式内容/文件集合/原所有者、权限、链接数核对，只有两侧一致才保存逻辑字节证明。后续事件日志有噪声时，对这些小型编译缓存重新做内容证明；完全相同才能跳过预热。真实内容或权限/集合变化、读取不稳定、超预算仍回原native流程。游戏目录不进入这项字节扫描。上限512MiB与100000文件，单次读取缓冲1MiB，不常驻库副本，不以元数据忽略代替内容证明。

定向测试新增只改时间属性、原生验证期间产物变化、证明预算不足及权限变化等反例。最终完整定向检查351项通过。整包收尾使用已成熟的本轮隔离缓存，仅两次暖启动确认登记及实际复用，不再重复冷启动。

用户已明确：本版本不扩展白模专项日志/自动图像诊断，真实复现时保留现场debug。已有经验证的资源保护与回写修补保持，不将无错误日志或本次站桩当作白模已解决。
